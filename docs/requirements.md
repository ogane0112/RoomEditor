# 3D部屋編集ツール 要件定義書

## 1. 概要

### 1.1 プロダクト名(仮)
未定(仮称: RoomEditor)

### 1.2 目的
実際の部屋を3Dスキャンして取り込み、ブラウザ上で家具の移動・削除・色変更などを手動で編集できるツールを作る。
将来的にAIによる自動コーディネート機能を追加することを見据えるが、フェーズ1では手動編集のみをスコープとする。

### 1.3 背景
- Zennの記事「EdiRoom(いじる〜む)」を読み、部屋を編集可能な3D空間として持つという発想に興味を持った
- EdiRoomはAI HACK 2026向けにAIコーディネート・見積もり・カタログ連携まで含む大規模なプロダクトだが、
  今回はその中核である「編集できる3D部屋」の部分だけを個人開発として作る
- Claude Codeを使って実装する

### 1.4 開発体制
- 個人開発
- 実装はClaude Codeに依頼する

---

## 2. スコープ

### 2.1 フェーズ分け

| フェーズ | 内容 |
|---|---|
| フェーズ1(今回の対象) | 3DスキャンGLBの読み込み・表示、家具の手動編集(選択・移動・回転・色変更)、保存/再読込 |
| フェーズ2(将来) | 家具の自動認識(Grounding DINO / SlimSAM等) |
| フェーズ3(将来) | AIによる自動コーディネート提案 |
| フェーズ4(将来) | 見積もり機能、カタログ連携 |

### 2.2 フェーズ1でやること
- 3DスキャンされたGLBファイルをブラウザにアップロードして表示する
- シーン内のオブジェクト(メッシュ)をクリックで選択する
- 選択したオブジェクトを移動・回転できる(TransformControls)
- 選択したオブジェクトの色を変更できる
- 選択したオブジェクトを削除できる
- 編集内容(位置・回転・色)をUndo/Redoできる
- 編集した部屋の状態をブラウザ内(IndexedDB)に保存し、再読込できる

### 2.3 フェーズ1でやらないこと
- サーバーへのデータ送信・保存(スキャンデータは機微情報として扱い、ブラウザ内処理に限定)
- 家具の自動認識・自動分離(GLB内のメッシュ単位での選択に留める)
- AIによる会話型コーディネート
- 見積もり自動生成
- 家具カタログからの商品差し替え
- ログイン・複数ユーザー対応

## 3. 機能要件

### 3.1 GLBインポート
- ローカルファイル(.glb)をドラッグ&ドロップ、またはファイル選択でアップロードできる
- アップロードしたGLBを3Dシーンに配置し、カメラで自由に見渡せる(オービットコントロール)

### 3.2 オブジェクト選択
- シーン内のメッシュをクリックすると選択状態になる(ハイライト表示)
- 選択中のオブジェクト名・情報をサイドパネルに表示する

### 3.3 移動・回転
- 選択したオブジェクトに対してTransformControls(移動・回転ギズモ)を表示する
- ドラッグ操作でオブジェクトの位置・回転を変更できる

### 3.4 色変更
- 選択したオブジェクトに対してカラーピッカーを表示し、マテリアルの色を変更できる

### 3.5 削除
- 選択したオブジェクトをシーンから削除できる(取り消し可能)

### 3.6 Undo/Redo
- 移動・回転・色変更・削除の操作履歴を保持し、Undo/Redoできる
- 履歴はセッション中のみで良い(保存データに含めるかは実装時に検討)

### 3.7 保存/再読込
- 現在の部屋の状態(各オブジェクトのtransform・色・削除フラグ)をIndexedDBに保存できる
- 保存した状態を再読込し、同じ部屋を復元できる
- 複数の部屋(プロジェクト)を保存・切り替えできるようにする

---

## 4. 非機能要件

### 4.1 セキュリティ・プライバシー
- 3Dスキャンデータ(メッシュ・テクスチャ含む)はブラウザ内(クライアントサイド)のみで処理し、サーバーには送信しない
- 保存データもブラウザのIndexedDBに留め、外部送信は行わない(フェーズ1の時点ではサーバーレス構成)

### 4.2 動作環境
- PCブラウザで動作すること(Chrome想定)
- スマホでの動作は必須ではないが、将来的な対応は妨げない設計にする

### 4.3 パフォーマンス
- 一般的な部屋スキャン程度のポリゴン数(数万〜数十万ポリゴン)で滑らかに操作できること

## 6. データ構造(案)

### 6.1 部屋(Room)
```
Room {
  id: string
  name: string
  glbFileName: string
  glbData: Blob (IndexedDBに保存)
  objects: RoomObject[]
  createdAt: string
  updatedAt: string
}
```

### 6.2 オブジェクト(RoomObject)
```
RoomObject {
  id: string          // GLB内のメッシュ/ノードID
  name: string
  position: [x, y, z]
  rotation: [x, y, z]
  color: string | null   // 上書きした色(nullは元の色を使用)
  deleted: boolean
}
```

## 7. 画面要件(概要)

- **メイン画面**
  - 中央: 3Dビューア(オブジェクト表示・選択・操作)
  - 右サイドパネル: 選択中オブジェクトの情報、色変更UI、削除ボタン
  - 上部ツールバー: GLBインポート、Undo/Redo、保存、部屋一覧への切り替え
- **部屋一覧画面**
  - 保存済みの部屋をサムネイル(または名前)で一覧表示、選択して開ける

---

## 8. 制約事項・前提

- GLBファイルは事前に3Dスキャンアプリ等で取得済みであることを前提とする(スキャン機能自体はスコープ外)
- GLB内のメッシュ分割の粒度に依存する(1つのメッシュが複数の家具を含む場合、個別選択できない可能性がある。フェーズ1ではこの制約を許容する)
